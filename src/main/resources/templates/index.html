    About the algorithm
    
        
    
            
    
                
    Idea
    
                
    Given a text y of length n and a pattern x of length m,
                    the algorithm slides a window of length m over the text. Instead of comparing from left to
                    right like the naive algorithm, each attempt compares the pattern positions in the order
                    1, 2, …, m−1 and finally 0.
    
                
    Looking at x[1] first allows a shift of two positions in some cases
                    without ever skipping an occurrence — hence “not so naive”.
    
            
    
            
    
                
    Preprocessing — O(1)
    
                
    
                    
    Conditionkell
    
                    
                    
    x[0] == x[1]21
    
                    
    x[0] != x[1]12
    
                        
                
    
                
    k: shift when x[1] ≠ y[j+1]. ell: shift when
                    x[1] = y[j+1], whether or not an occurrence was found.
    
            
    
            
    
                
    Searching phase
    

    j ← 0
while j ≤ n − m:
    if x[1] ≠ y[j+1]:
        j ← j + k
    else:
        if x[2..m−1] = y[j+2..j+m−1] and x[0] = y[j]:
            report j
        j ← j + ell
    
            
    
            
    
                
    Why a shift of 2 is safe
    
                
    If x[0]=x[1] and y[j+1]≠x[1], then y[j+1]≠x[0], so no occurrence can start at
                    j+1. If x[0]≠x[1] and y[j+1]=x[1], then again
                    y[j+1]≠x[0]. In both cases position j+1 is skipped safely, so overlapping
                    occurrences are never lost.
    
            
    
            
    
                
    Complexity
    
                
      
                    
    • Preprocessing: O(1) time and space (a single comparison).
      • 
                    
    • Search, worst case: O(n·m) — e.g. y = aⁿ, x = aᵐ.
      • 
                    
    • Extra space: O(1), excluding the stored positions.
      • 
                    
    • Average: slightly sub-linear by a constant factor in the number of comparisons,
                        thanks to the shifts of 2.
      • 
                
    
                
    The counters shown in the results are character comparisons for a given input — an
                    empirical measure, not the asymptotic time complexity.
    
            
    
            
    
                
    Implementation notes
    
                
    Business class NotSoNaive (pure Java, no indexOf, regular expressions or
                    other matchers). Positions are collected in the SEED structure
                    ufps.util.colecciones_seed.ListaCD (O(1) insertion at the end) and exposed through a
                    SEED Secuencia for indexed access. One-character patterns have no x[1],
                    so each window compares only x[0] and shifts 1. Reference: C. Charras & T. Lecroq,
                    Exact
                        String Matching Algorithms — Not So Naive.
